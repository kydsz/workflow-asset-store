# 配方身份按「模板哈希」归并，运行值留在生成记录

同一条 ComfyUI 工作流换个提示词或 seed 再跑一次，不该产生第二个配方；但完全相同的两份文件被重复入库也不该产生第二个配方。我们决定配方的身份 = **剥离运行相关值与画布噪音后的规范化 JSON 的 SHA-256**：正向提示词（首个文本编码节点）与各 KSampler 的 seed 替换为哨兵 `__was_prompt` / `__was_seed`，`extra` / `config` / 节点坐标 / 前端簿记字段整体丢弃，再做确定性键序规范化后取哈希。产物文件仍按 ADR-0004 以**原始内容哈希**命名落盘——两者口径不同且不可互换：文件哈希回答「这是不是同一个字节流」，模板哈希回答「这是不是同一份可复用配置」。

当次的提示词、seed 与其它参数属于那一次运行，写在生成记录上，配方本身只存模板。导出复现时（`exportWorkflow`）把哨兵回填为某条记录的当次值，因此「带参导出」不需要为每次运行另存工作流副本。备选方案「按文件哈希归并」被否决，因为它把画布平移这类无意义差异当成新配方；「按提示词文本归并」则会把同一工作流的不同分支用法错误合并。

存量的旧口径配方（改前按未剥离内容落库）在匹配时按其自身内容再剥离一次做二次匹配，命中即自愈归并，不做一次性数据迁移。词汇见 `CONTEXT.md`。
