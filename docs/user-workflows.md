# 操作流程规格

术语以 `CONTEXT.md` 为准（生成配方 / 生成记录 / 产物 / 入库 / 归属人），结构约束见 `docs/architecture.md` 与 ADR。本文描述 MVP（单人、本地自托管、图片+视频、无登录）的完整操作流程。

**这是目标规格，不是实现清单。** 每节末尾的「实现状态」按 2026-09-26 的代码现状标注：✅ 已可用 / ⏳ 部分实现 / ❌ 未开工。与规格冲突处以本文为准，未实现的项即待办。

## 0. 首次启动

1. 用户克隆仓库、`pnpm install && pnpm dev`，浏览器打开 `localhost:3000`。
2. 系统检测数据目录不存在 → 引导初始化：创建 SQLite 库、存储目录 `data/files/`、缩略图目录 `data/thumbs/`，写入默认配置（存储模式默认 copy）。
3. 空库首页显示引导卡片：「上传 ComfyUI 导出文件」+「扫描输出目录」两个入口。CLI 与 MCP 此时已可用（同库文件）。

**实现状态** ⏳ —— 首步与建库均已可用（首次访问即自动 `mkdir` + 建 schema，无需手工初始化）。但：无 `thumbs/`（前端经 `/api/files/**` 直读原文件）、无「默认配置」概念（copy 为唯一缺省，reference 需显式指定）；空库无引导卡片，只有侧栏与上传对话框入口；MCP 需先 `pnpm build` 再 `node apps/mcp/dist/server.js`，CLI 不存在。

## 1. 入库：四条路径

### 1a. Web 手动上传（主路径，ComfyUI 产物）

1. 用户把 ComfyUI 导出的 PNG/JSON（可多选）拖入上传框。
2. 系统按文件扩展名 + 内嵌元数据嗅探，选择 extractor（当前仅 ComfyUI）。
3. ComfyUI extractor 解析：提示词、采样参数（seed/steps/cfg/sampler/模型）、完整工作流 JSON、节点图快照。
4. 解析成功字段直接入库；解析失败/缺失字段置 `needs_manual`，进入待补录状态（记录仍可见，带黄色标记）。
5. 一批文件如果是同一次运行的多输出（相同 workflow_run_id / 时间窗口 + 相同参数），合并为 **1 条生成记录 + N 个产物**。
6. 按 copy 模式：媒体与工作流 JSON 复制进 `data/files/`，生成缩略图（sharp / ffmpeg 抽帧），写库。
7. 页面即时反馈：新记录卡片 + 解析结果摘要（识别到的提示词、关联/新建的配方）。

**边界**：
- 重复入库以文件内容哈希去重，提示「已存在于记录 #N」，可选择强制另存。
- 上传非 ComfyUI 图片（无内嵌工作流）→ 落到 1d 手动补录表单，尽量从常见元数据（EXIF、A1111 式 prompt 字段）做 best-effort 预填。

**实现状态** ⏳ —— 1/2/4/5/7 与去重提示已可用：拖拽（全局投放区或上传对话框，大文件需留意 `next.config.ts` 的 `experimental.serverActions.bodySizeLimit`）、`sniffSource` 嗅探、同批次按运行键合并、解析缺失字段标 `needs_manual`（含 `mediaType` 歧义）、结果以 sonner 弹层汇总并给记录链接、按 `fileHash` 命中已有记录时返回 `existing` 而非重复入库。3 只有提示词 + KSampler 采样参数 + 工作流 JSON，**无节点图快照**。6 无缩略图/抽帧。去重后的**强制另存**没有出口（只能改用手动补录表单）；非 ComfyUI 图片不做 EXIF/A1111 预填，只会落到「待补录」等人工填。

### 1b. CLI 批量扫描

`asset scan ~/ComfyUI/output --since 7d`：
1. 遍历目录，对每个媒体文件走与 1a 相同的 extractor 管线。
2. 哈希去重跳过已入库文件，输出摘要：`新增 N 条记录 / 跳过 M 个重复 / 待补录 K 条`。
3. `--watch` 模式常驻监听新文件（低频轮询即可，不做 fsnotify 承诺）。

**实现状态** ❌ —— `apps/cli` 仅有 `package.json` 占位。core 的 `ingestFiles` 已接受多源文件，扫描器只是它外面的目录遍历 + 时间过滤，属未开工的薄壳。

### 1c. AI 经 MCP 自报入库

生成类 Agent 完成产出后调用 `ingest` 工具：传文件路径（本机可读）+ 结构化参数（tool、prompt、recipe 引用、生成时间）。系统按 reference 或 copy 安置文件、建记录。用于「AI 生成完自己记账」闭环；AI 提供的字段视为**声称值**，若文件内嵌元数据可解析则以解析值为准并标记冲突。

**实现状态** ✅（冲突标记为 ⏳）—— `ingest` 已接受显式字段并优先采用显式 `recipeId` 关联；但「解析值覆盖声称值并标记冲突」未实现，当前是**显式字段优先于解析值**（`has(field)` 短路），无冲突位。

### 1d. 云端工具手动补录（可灵 / Runway / Vidu 等）

1. 用户点「新建生成记录」，选生成工具（无工作流文件类）。
2. 填表：上传或引用视频文件、粘贴提示词、选填负面提示词/模型版本/画幅/时长/参考图链接。
3. 视频文件大 → 表单显式提供两种安置选择：复制到库（默认）或引用原路径（显示当前磁盘剩余空间提示）。
4. 保存即成一条记录（无配方关联，`recipe: null` 是合法状态）。

**实现状态** ⏳ —— 上传对话框的「手动补录」tab 可建记录（工具、提示词、备注、关联配方），无工作流文件的记录合法。负面提示词/模型版本/画幅/时长没有专属字段，只能进 `params` JSON 或备注；表单无 copy/reference 二选一，也没有磁盘余量提示。

## 2. 待补录队列

- 首页角标 + 独立页面 `/incomplete` 列出所有含 `needs_manual` 字段的记录。
- 逐条打开：已解析字段预填、缺失字段高亮，补完保存后清除标记。
- 允许「忽略该字段」——忽略后不再提醒（防止视频类永远拿不到的参数卡住队列）。

**实现状态** ⏳ —— `/incomplete` 页与详情页的待补录卡片（原因码有中英文案）均可用，PATCH 保存会按 `resolveManual` 清除对应标记。**「忽略该字段」未实现**：没有"已忽略"状态，补不到的字段会永久留在队列里。

## 3. 浏览与检索

- `/`：瀑布流（图 + 视频首帧缩略图），按生成时间倒序；视频卡片带时长角标，悬停预览。
- 筛选器：生成工具 / 媒体类型 / 有无配方 / 待补录状态 / 时间范围；全文搜索命中提示词、备注、配方名、参数值。
- 排序：时间 / 使用配方的生成次数。
- 结果页每条卡片右键菜单：查看详情、复制提示词、再补一次（跳转配方）、移入引用模式。

**实现状态** ⏳ —— 瀑布流、按时间倒序、图片直读原文件、卡片可播视频（非首帧）；筛选器有 全文 / 工具 / 媒体类型 / 有无配方 四项（下拉即选即生效），core 检索另支持 `needsManual` 与 `since/until`，**Web 未暴露时间范围与待补录筛选**（待补录走 `/incomplete`）。排序固定 newest-first，无按使用次数排序；无时长角标；卡片无右键菜单，操作在详情页与配方卡片上。

## 4. 详情页（单条生成记录）

自上而下：
1. 媒体查看器：图片缩放/原图，视频播放器；批跑产物以图集翻页。
2. 溯源面板：生成工具、生成时间、关联配方（可空，点击进入配方页）、当次提示词（一键复制、一键「复制全部参数」为文本/JSON）、全部参数表格（seed/steps/cfg/模型/画幅/时长…）。
3. 元数据区：原始内嵌元数据 JSON 视图、`needs_manual` 标记一览、入库路径（upload/scan/mcp/manual）与入库时间。
4. 文件区：产物在库内的安置状态（copy 路径 / reference 原路径 + 健康检查绿/红点）、下载、打开所在目录。
5. 操作：编辑字段、复制此记录为新草稿（换提示词再生成时用于对照）、删除（记录与 copy 模式文件一并进 `data/.trash/`，30 天可恢复；reference 模式永不触碰原文件）。

**实现状态** ⏳ —— 1（图片/视频 + 多产物网格，非翻页）、2 的溯源与当次参数表格（`params` JSON 原样展开）、3 的待补录一览、4 的路径 + copy/reference 标注 + 内容哈希前缀均已有。缺：提示词与参数的一键复制按钮、原始内嵌元数据 JSON 视图、reference 文件的断链健康检查、打开所在目录；入库途径字段目前只有 `auto-extract` / `manual` 两值，分辨不出 upload / scan / mcp 哪条路径；**5 的编辑与关联配方已可用（PATCH），复制为新草稿与删除/回收站完全没有**（无 DELETE 路由）。

## 5. 配方（Recipe）流程

- 配方页 `/recipes`：列表分三 tab——工作流文件 / 参数预设 / 提示词模板。
- **自动建档**：1a/1b 入库时按工作流 JSON 内容哈希归并到同一配方；第二次使用同一 ComfyUI 工作流不再产生重复配方。
- **纯收藏**：`新建配方` → 选形态「提示词模板」，粘贴文本 + 标注适用工具即可保存，无需任何生成记录。
- 配方详情：历次生成记录时间线、使用统计（次数、常用参数区间）、配方正文查看器（工作流 JSON 结构树 / 模板文本）。
- **复用导出**：ComfyUI 工作流提供「带参导出」——选一条生成记录，把当次提示词/seed 注入 JSON 后下载，直接拖回 ComfyUI 复现。

**实现状态** ✅（详情查看器为 ⏳）—— 三形态 tab（URL `?kind=`）+ 关键词过滤、入库按**模板哈希**自动归并（ADR-0007，比"内容哈希"更宽：只改提示词或 seed 不产生新配方）、纯收藏建档（提示词模板/参数预设必须带内容，工作流文件可先建档后补挂）、复制配方、详情页的记录列表与使用统计（次数 + 最近使用）、带参导出（注入首正向文本编码节点与 KSampler seed，兼容 API 与 UI 两种 JSON 形态）。缺：常用参数区间、工作流 JSON 结构树（当前是下载/原文）。

## 6. 维护与备份

- `asset doctor`（CLI 或 Web 设置页触发）：校验 reference 模式文件是否断链、缩略图缺失重建、DB 与 `data/files/` 孤儿文件对账。
- 备份 = 拷贝 `data/` 整个目录；恢复 = 指 `ASSET_DATA_DIR` 到新位置。无云同步承诺。
- 导出：全库或筛选结果导出为 JSONL（含元数据，媒体可选打包）。

**实现状态** ⏳ —— 备份/恢复按描述可用（`ASSET_DATA_DIR` 缺省 `./data`，Web 侧相对 `process.cwd()`）。`doctor` 与 JSONL 导出未开工（依赖 CLI）。

## 7. AI 侧（MCP 工具面）

`apps/mcp` 暴露的最小工具集：
- `search_generations(query, filters) → 记录摘要列表`
- `get_generation(id) → 完整溯源`
- `list_recipes() / get_recipe(id)`
- `ingest(...) → 见 1c`
- `record_stats(recipe_id) → 使用统计`

**实现状态** ✅ —— 六个工具全部落地（`apps/mcp/src/tools.ts` 的 handler 直调 core，`server.ts` 做 stdio 与 zod 入参）。`search_generations` 的参数与 core `SearchQuery` 一一对应（含 `needs_manual`、`since/until`、`sort`），因此 AI 侧的检索面比 Web 筛选器更全。写侧目前只有 `ingest`，编辑/删除记录与配方的工具尚未提供。

## 8. 明确不做（MVP 边界）

多用户登录与权限（owner 字段已预留，见 ADR-0005）、云端同步、音频/3D 产物、非 ComfyUI 本地工具的自动解析、跨设备合并库、在线分享链接。
